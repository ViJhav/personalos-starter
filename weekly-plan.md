## How this file works

Delete this section once it is second nature.

**It is a surface, not a store.** Everything on it already lives somewhere durable, in a project or area file. Deleting a line loses nothing. That is what makes it safe to rewrite from scratch every week.

**The sections split by kind, never by priority.** Each answers a different question: what must not get crowded out, what you are choosing to move, what is fixed by the calendar, what you are deliberately skipping.

Do not add Must / Should / Optional tiers. This is the most common way a plan like this fails. "Should" becomes a graveyard within about three weeks: things go in, nothing comes out, and eventually you stop reading the section at all. One flat list makes every item face the same question.

For the same reason, do not add a "carryovers" section. An unfinished item gets an explicit call at the next review: re-chosen into This week, moved to Waiting with a reason, or left in its project file with no plan line at all. What it never does is silently ride along for six weeks unexamined.

**Do not cap the number of items.** A cap sounds disciplined and does not work: the only way to hit it is bundling unrelated tasks onto one line, which is a priority tier in disguise and destroys per-item tracking. The honest filter is "is this genuinely happening this week?" A long list is a signal to re-read it, not a rule violation.

**Do not build a day-by-day grid.** That is a second calendar, and it will start disagreeing with your real one.
